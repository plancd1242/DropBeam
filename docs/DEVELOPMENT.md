# Development and verification

## Local runtime

`npm run dev:all` runs the Worker locally, waits for its health response, starts Vite on loopback, prints both URLs, and launches Electron against the actual frontend URL. It starts at ports 8787 (Cloud) and 5173 (UI), skipping occupied ports. The Worker debugger uses an available port starting at 9230. No unrelated processes are stopped.

`npm run dev:ui` is a browser preview. Its preferences live in that browser's localStorage, separate from the desktop's preferences. Native file selection and mDNS do not run in the browser. The preview does not call Gmail or bypass the desktop bridge.

The native app stores `settings.json` under Electron's app-specific user data directory (on macOS, typically `~/Library/Application Support/dropbeam`). Corrupt settings cause a visible startup error and are not overwritten. Rename the corrupt file manually to recover defaults. Quitting the last window exits the native app; background transfers are not implemented. The development launcher keeps the frontend and Worker running until Ctrl+C.

When a terminal is closed, its dev servers may stop. Relaunch `npm run dev:all` and use the addresses it prints. If another copy is already open, Electron focuses it; close that copy before starting a different build for comparison.

## Public desktop configuration

The launcher reads only `DROPBEAM_*` values from Vite's environment files for use by the native process; they are not secret storage. Existing shell values override the example/local file. `.env` is ignored. `npm run dev:all` uses its local backend by default.

- `DROPBEAM_API_URL`: optional Cloud base URL. HTTPS is mandatory except explicit development mode with `http://127.0.0.1:<port>`.
- `DROPBEAM_ENV`: development mode for local HTTP. The development launcher sets it.
- `DROPBEAM_DEV_URL`: generated by the launcher; only validated loopback URLs are accepted, and packaged apps ignore it.
- `DROPBEAM_TEST_DATA_DIR`: test-only native profile isolation; ignored by packaged apps.
- `DROPBEAM_SMOKE_URL`: optional URL used to smoke-test an already-running Vite server; omit to test built assets.

Packaged applications currently read public Cloud configuration from their process environment. A maintainer-owned public production URL must be configured in a future distribution build; there is no bundled deployed endpoint today. End users must never need provider credentials.

## Checks

Run `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, and `npm run build:cloud`.

`npm run test:desktop` launches a real Electron window with a temporary profile, exercises navigation, settings, Premium preview, renderer isolation, and file hashing. The test substitutes a fixture for the OS chooser only; actual IPC validation and filesystem hashing execute. It sends no email. Screenshots are saved in ignored `.artifacts/` and the temporary profile is deleted. Native chooser interaction and two-computer networking should also be tested by a human.

`npm run test:discovery` runs two real mDNS instances on one computer, verifies mutual discovery, then tears them down. This is a network smoke test, not evidence of cross-machine or cross-platform transfer support. During this continuation it timed out: sockets opened, but a separate diagnostic observed zero incoming multicast packets. The cause remains unconfirmed; no OS firewall or network settings were changed.

## Packaging

`npm run package` creates an unpacked local app for the host platform. It does not create a published release or a signed/notarized installer. macOS DMG, Windows NSIS, and optional Linux AppImage targets are configured but need platform-specific verification, branding, signing, and distribution decisions. Do not claim Windows support has been tested on macOS alone.

## Common failures

- macOS may require local-network permission before discovery works. Firewalls, guest Wi-Fi isolation, and disabled multicast can prevent discovery; the UI reports errors or no peers rather than inventing devices.
- Frontend hot reload uses a development-only script nonce and loopback WebSocket permission. Production CSP permits neither inline scripts nor dev WebSockets.
- A valid Premium request returning 503 with no credentials is expected. It is not a successful email.
- Worker output under `dist/cloud` is a dry-run artifact only. Wrangler state/logs remain in ignored `.wrangler` directories. Telemetry is disabled in the Worker configuration.

The launcher explicitly removes inherited `ELECTRON_RUN_AS_NODE` from the Electron child environment; VS Code can set this flag and otherwise cause Electron to start as a Node process instead of a desktop app.
